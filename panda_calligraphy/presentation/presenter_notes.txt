SLIDE 2 — What CalliRewrite recovers

0:30–1:20

A calligraphy image records where ink ended up, but it does not directly record the order of strokes, where the pen lifted, or how the writing tool moved. CalliRewrite estimates a plausible sequence of writing actions from that image. Its central feature is learning without labelled writing demonstrations for the target glyph. The official examples cover several fonts and writing tools. A still image can admit more than one plausible order, so we should not interpret the result as a unique reconstruction of the original human motion. The official physical platform shown in this figure is a Dobot. Our Panda scene is a later local extension.

SLIDE 3 — The original two-stage method

1:20–2:15

Read the official method figure from top to bottom. Coarse sequence extraction uses an image encoder and a recurrent model to propose Bézier stroke segments. Rendering these proposals back into an image supplies a reconstruction signal. The second stage samples the resulting curves and passes them to a simulated writing tool. A soft actor-critic policy then adjusts the control sequence under the tool model. This division matters: the first stage estimates a useful stroke structure, while the second stage adapts the geometry to the behavior of the chosen utensil. In our workflow, extraction and refinement finish before the Viser replay starts.

SLIDE 4 — Coarse sequence extraction

2:15–3:20

The model works through dynamic image windows. It predicts local quadratic Bézier geometry, a pen state and stroke width, then updates its internal view of the drawing. During training, image reconstruction and regularization encourage plausible segments with useful continuity. Our adapter must recover global image coordinates from the moving windows. It also preserves every inference round and pen-up event. The three pictures show the actual dataset image 0, its pretrained reconstruction, and the model's colored sequence visualization. This output contains ten decoded stroke groups. That count describes the model's grouping, rather than a claim about the canonical pedagogical stroke count of the character.

SLIDE 5 — Tool-aware refinement

3:20–4:25

The refinement stage uses the official CalliEnv environment. The state summarizes progress along the coarse sequence and properties of the current writing footprint. The SAC policy proposes bounded changes near the coarse path. The tool model produces a footprint, and the reward measures how its marks agree with the input and the desired writing behavior. During training, an exponential moving average also updates the skeleton. That distinction becomes important in our results: a better final drawing can reflect skeleton updates as well as the policy. The repository provides coarse extraction weights. The refinement policies used here were trained locally for the selected glyph and brush, rather than downloaded as a universal Panda controller.

SLIDE 6 — Our Panda simulation environment

4:25–5:15

Viser supplies the interactive browser scene, robot meshes and controls. Our Python code supplies the kinematics, trajectory timing, contact visualization and raster updates. The Panda model comes from its URDF, and the solver holds the tool upright. We keep the three software environments separate: TensorFlow for extraction, PyTorch for reinforcement learning, and a lighter Python environment for playback. A saved NPZ is the interface between them. The viewer therefore needs no active neural model or CUDA GPU when it replays an existing example. This scene is a geometric and kinematic simulation. It does not run torque control, full rigid-body dynamics or a calibrated physical brush solver.

SLIDE 7 — Image coordinates and robot motion

5:15–6:15

The imported image uses u for columns and v for rows. We place an eighteen-centimetre glyph in the centre of a thirty-six-centimetre sheet. Image-right points along positive Panda Y, while image-up points along negative Panda X. This convention keeps the image upright when viewed from above and avoids reflecting the character. The chart plots the actual imported centreline in that top-view convention. Inverse kinematics converts each target into a robot configuration while keeping the tool down. Between stroke groups, the trajectory adds a twenty-five-millimetre lift. The nominal writing speed is twenty-five millimetres per second, with timing stretched if a URDF joint-speed limit requires it.

SLIDE 8 — The deformable brush in Viser

6:15–7:20

This close-up shows the current model-output viewer, rather than the older scripted brush demonstration. The brush has a fixed ferrule and a soft-looking tuft. A cubic spine connects the tuft root to its tip. In contact, the tip sits on the paper plane and the lower part of the mesh expands according to the exported footprint. Heading gives the contact region a direction. The radius-to-compression conversion is a virtual calibration: radius in metres equals twice the nominal penetration. That height controls the Panda pose and the visual tuft. The code recomputes geometry each frame. There is no mass, stiffness integration or measured force behind this particular mesh, so it should be described as illustrative deformation.

SLIDE 9 — Why a cubic Bézier curve?

7:20–8:15

A cubic Bézier curve uses four control points. The first and last are the endpoints, while the two intermediate points control the directions near those endpoints. This makes it convenient for a brush: the root can follow the ferrule, the end can touch the paper, and the intervening points create a smooth bend. The graph shows coordinates from an actual contact state in our replay, projected along the footprint heading. The dashed control polygon is a geometric construction. The smooth curve is the spine that the mesh follows. It is inexpensive to evaluate and easy to shape, but it does not by itself solve elastic mechanics. Also distinguish this cubic visual spine from the quadratic curves that CalliRewrite extracts from the glyph.

SLIDE 10 — How the ink appears

8:15–9:05

The ink and the 3D tuft have different jobs. Each saved drawing sample contains a footprint anchor, radius, length and heading. The replay computes the achieved Panda tip through forward kinematics and places the corresponding native footprint at that location on a two-dimensional canvas. It then sends the updated canvas back to Viser as the paper texture. Stamps occur only at exported contact samples. The extra joint interpolation used for smooth animation adds no new ink. The released renderer combines triangular geometry with a disk. It passes a normalized radius into a pixel-radius operation. This unit convention may contribute to the jagged marks shown here; that contribution has not been separately tested. We preserve that behavior to test faithful replay and clearly record it as a limitation.

SLIDE 12 — Replay preserves the exported drawing

11:35–12:25

The strongest result from this pilot concerns integration fidelity. These images show the native exported drawing and the Panda-achieved raster for dataset image 0. Their foreground masks match exactly at three hundred by three hundred pixels. The second refined example also achieves exact native-mask agreement, and its live browser canvas matches the offline replay. We tested both coarse and refined paths for both glyphs, giving four trajectories. The checks cover pose convergence, joint limits, nominal joint speeds, ferrule clearance and ink scheduling. We also sampled intermediate joint motion. This does not establish robot collision safety or physical accuracy. One hundred percent here means agreement with the exported drawing, rather than agreement with the desired input character.

SLIDE 13 — What refinement improved

12:25–13:25

This chart separates four conditions using the same native brush renderer. The two colors represent the two glyphs. Comparing fresh coarse geometry with zero action against the final EMA-plus-policy output gives gains of about one point one four and two point nine four percentage points. However, replaying the training-updated skeleton with zero actions retains most of that gain. Applying the trained policy to fresh coarse geometry slightly worsens both glyphs. On the selected EMA skeleton, the policy helps one glyph and hurts the other. The runs used fifty thousand and twenty thousand collected steps, one seed and selection on the same glyph. Our runner also uses separate critic backbones and bounded settings, so these results are a pilot rather than a complete reproduction of the paper.

SLIDE 14 — How to run the demonstration

13:25–14:15

On this machine, open a terminal at the repository root and run the provided launcher. It selects the existing viewer environment, clears inherited Python paths and loads the bundled refined example. The script first performs the offline trajectory checks, then starts Viser. Open the printed localhost address, which defaults to port eighty eighty-four, and press Play. Replay repeats a finished run, while Restart and clear resets it. A saved trajectory does not require a GPU for playback. For a new character, supply a black-on-white image to the extraction verifier first. The resulting coarse NPZ can already be drawn. Tool-aware refinement is an additional experiment, and its selected trajectory can be passed to the same viewer.

SLIDE 15 — Feasibility and remaining validation

14:15–14:50

The practical outcome is that we can connect the pretrained extractor, a bounded refinement run and a Panda visualization without changing the official model code. The exported marks survive the robot replay exactly in the tested cases. The method-quality conclusion is narrower. We still need distinct held-out glyphs, repeated seeds and controlled comparisons of the renderer's radius convention. A physical Panda experiment would also need a measured tool transform, brush radius-height calibration, collision and acceleration checks, and an appropriate controller. The current mesh and kinematic scene provide a useful way to inspect the workflow and communicate it. They do not yet predict the ink left by a real brush with validated physical accuracy.
